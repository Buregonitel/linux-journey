# Devices

This section covers how Linux represents, discovers, organizes, and interacts with hardware and pseudo-devices.

The lessons focus on the `/dev` filesystem, device types and naming, the kernel's device model, `udev`, hardware discovery tools, and the `dd` command for low-level block copying.

## Key Concepts

### `/dev`

Linux exposes many devices through special filesystem entries called **device nodes**.

Examples include:

* disks and partitions
* terminals
* pseudo-devices
* random-number sources
* virtual devices

`/dev` provides a filesystem interface through which user-space programs can interact with kernel-managed devices.

### Device Types

Linux distinguishes several filesystem object types.

The most important device-specific types are:

* **Character devices** — provide data as a stream of characters or bytes.
* **Block devices** — provide access to data in blocks and are commonly used for storage devices.

Other filesystem objects, such as pipes and sockets, are not device nodes even though they can also provide communication interfaces.

### Device Names

Linux uses naming conventions to identify hardware and logical devices.

Common examples include:

* `/dev/sda` - a disk device
* `/dev/sda1` - a partition
* `/dev/nvme0n1` - an NVMe namespace/device
* `/dev/nvme0n1p1` - an NVMe partition
* `/dev/mapper/...` - device-mapper paths
* `/dev/disk/by-uuid/...` - persistent UUID-based references
* `/dev/disk/by-id/...` - persistent device identifiers

Persistent links can be preferable to relying only on names that may change when hardware configuration changes.

### sysfs

The `/sys` filesystem exposes information about the Linux kernel's device model.

It can be used to investigate relationships between:

* devices
* drivers
* buses
* kernel classes

Unlike `/dev`, which provides device access interfaces, `sysfs` primarily exposes information about how the kernel represents and manages devices.

### udev

`udev` operates in user space and processes device events generated by the kernel.

It can apply rules for:

* device permissions
* ownership
* naming
* persistent links
* other device-specific policies

This helps Linux create predictable and usable device interfaces when hardware appears or changes.

### Hardware Discovery

Several commands provide different views of the hardware:

```bash
lsusb
lspci
lsscsi
```

They can be used to investigate different parts of the hardware topology rather than treating all devices as one flat list.

### `dd`

`dd` performs low-level copying of data streams.

A typical structure is:

```bash
dd if=SOURCE of=DESTINATION bs=SIZE
```

Where:

* `if=` specifies the input
* `of=` specifies the output
* `bs=` controls the block size

Because `dd` can write directly to disks and other block devices, an incorrect destination can cause immediate data loss.

## Useful Commands

```bash
ls -l /dev
ls -l /dev/disk/
ls -l /sys/
lsusb
lspci
lsscsi
dd if=SOURCE of=DESTINATION bs=SIZE
```

For device investigation, it is useful to combine filesystem inspection with hardware and kernel information:

```text
/dev
  ↓
device nodes
  ↓
sysfs (/sys)
  ↓
kernel device model
  ↓
udev
  ↓
user-space device management
```

## What I Learned

* Linux represents many devices through special entries in `/dev`.
* Device nodes have different types and semantics.
* Block and character devices serve different access models.
* Device names follow conventions for physical disks, partitions, logical devices, and persistent references.
* `/sys` provides a view of the kernel's live device model.
* `udev` connects kernel device events with user-space device management.
* `lsusb`, `lspci`, and `lsscsi` provide complementary hardware views.
* `dd` is a powerful low-level tool that requires careful handling of its input and output paths.
